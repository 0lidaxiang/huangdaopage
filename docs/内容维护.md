# 内容维护

## 从原数据库重新导出

默认源目录为同级 `../huangdao`，数据库名为 `huangdao`。导出器使用已有表的 `site_state.id=1.payload`，在同一只读事务中读取快照及更新时间，随后回滚事务；不创建数据库/表、不启动后端、不初始化 seed、不调用管理员 API。

先启动原本机 MySQL。在本机编辑 `.private/mysql.cnf`，不要将密码发到聊天、写入命令参数或提交记录。目录权限应为 700，文件权限为 600。配置格式如下，其中密码仅在自己的编辑器中填写：

```ini
[client]
host=127.0.0.1
port=3306
user=root
password=
```

```sh
chmod 600 .private/mysql.cnf
npm run content:audit
npm run content:export
npm run content:check
```

可通过 `--mysql-config /安全配置路径` 指定已有配置；数据库名使用 `--database`，源目录使用 `--source`。也可从当前进程环境提供 `DB_PASSWORD`，导出器只传入子进程环境，不放到命令参数。仅接受本机 host，连接失败立即停止，不自动读取历史备份。

原始快照保存在 `.private/snapshots/`，完整逐条状态、排除原因及历史来源比较保存在 `.private/migration-audit.json`。这些文件均为 600 权限，不复制到 `public`、`.generated/public` 或 `dist`。

全量盘点包括源 `content/` 内容包、`artifacts/` 中实际含记录的 JSON、文件模式快照的存在情况；来源、文件哈希、数量、ID/slug、是否入库、差异字段及冲突决策均可核对。当前数据库中编辑过的记录优先保留。历史快照仅用于比对，不自动补入公开内容；内容包中未入库的记录需要先决定是否公开。

只有显式指定 `--snapshot <文件> --snapshot-origin <选择依据>` 才能从手动快照导出，来源会记录为 `explicit-snapshot`。不要把历史快照导出描述为当前 MySQL 迁移。重新导出会替换目标的公开内容，并清理上一轮数据库导出的失效媒体；若已在静态仓库改稿，先查看差异并保存这些改稿，再决定是否重新导出。

## 发布规则

沿用原后端 `published()`：状态为 `published` 或 `scheduled`，发布时间为有效的带时区 RFC3339，且不晚于导出时刻。公开产物把已到期 scheduled 标为 published。草稿、下线、回收站、无效时间和未来记录只出现在私密盘点，不进入可下载文件。

静态站不会在未来时间自动开放内容。定时文章到期后，需要重新导出、构建和部署。导出的公开内容源不含未来正文，因此仅重建旧内容源无法发布被排除的文章。

推荐 ID、关联 ID 只保留公开对象，顺序沿用数据库；话题数量由全量公开内容重新计算。文章标题、摘要、正文、作者、日期、事件年份、来源 URL、分类、话题、SEO、ID 和 slug 均保留。不会因为题材重叠而自动合并不同 ID 的文章。

## 在静态仓库直接维护

运行和更新静态站都不需要保留原仓库。修改 `content/articles/` 中的公开 JSON：正文使用 Markdown，其他字段延续现有格式。新增时复制同类公开记录作为结构模板，指定新 ID、唯一 slug、真实来源和日期；保持 `status` 为 `published`。修改 `content/site.json` 可调整话题、路线、阶段、导航、主推、推荐顺序、公众号、关于和咨询。

```sh
npm run content:sync
npm run content:check
npm run build
npm run test:e2e
```

`content:sync` 明确接受当前本地公开内容，重建索引、话题计数、正文哈希和维护记录，保留最初导出时间、来源及原始公开 ID 基线。此流程不读取数据库，也不自动回写原站。删除文章前应先修正关联；修改已有 slug 会改变历史 URL，优先保留原 slug。

**草稿和待定时发布内容放入 `.private/`，不要放进可提交的 `content/` 或 `public/`。** 同步器拒绝未来时间和非 published 状态；JSON 文件本身仍是公开仓库文件，应只放已决定公开的资料。

本地图片放入 `public/uploads/`，记录中使用 `/uploads/文件名`；支持文章封面、正文内联和引用式 Markdown 图片、话题图片及二维码。构建会加上部署前缀。二维码为空时显示“二维码待配置”，公众号名沿用站点设置。静态站自行维护的微信/小红书二维码和链接在 `content/site-overrides.json`，构建时覆盖订阅字段，重新导出不覆盖该文件；详见[订阅二维码](订阅二维码.md)。

Markdown 禁用原始 HTML，保留 GFM、代码高亮、表格、列表、引用和图片。不要把脚本、iframe 或旧站 `/api` 地址当成正文功能；构建会检查本机服务引用和缺失媒体。
