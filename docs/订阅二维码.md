# 微信与小红书订阅

订阅卡片与“订阅荒岛来信”弹窗均提供微信公众号和小红书两个入口。图片在本站本地托管，不依赖 GitHub 或小红书图片服务；手机可直接点击平台链接，或长按图片识别/保存。二维码使用白色底板，在亮暗主题中保留对比度。

## 本轮素材来源

- 微信二维码由用户提供：[原始图片](https://raw.githubusercontent.com/0lidaxiang/0lidaxiang/main/assets/wechat-qrcode.jpg)，尺寸 430×430，49,536 字节。以原像素无损压缩为 `public/uploads/subscriptions/wechat-qrcode.webp`，33,964 字节，约减小 31%。没有裁切或改写二维码。
- 微信二维码实际解码为 `http://weixin.qq.com/r/mp/OCpbQ4TEq9nUrcAg938q`，“打开公众号”使用这个真实目标地址。
- 小红书由用户提供[主页分享链接](https://xhslink.com/m/7mMhFIxAvCX)。该地址为个人主页分享地址，并非图片资源；据此生成准确的二维码 `public/uploads/subscriptions/xiaohongshu-qrcode.png`，尺寸 430×430，2,152 字节，Q 级纠错并保留四模块静区。
- 小红书二维码实际解码为用户原始分享链接，按钮也使用同一链接。访问小红书时可能由该平台要求登录、打开客户端或完成验证，本站不代替其访问流程。

两张最终图片均已使用本机 Vision 解码，确认压缩后的微信图片与原图目标一致、小红书图片目标与用户链接一致。

## 后续维护

修改 `content/site-overrides.json` 中的 `settings`：

- `qrCode`：微信公众号二维码本地地址。
- `wechatUrl`：点击“打开公众号”的目标。
- `xiaohongshuUrl`：用户提供的小红书分享链接。
- `xiaohongshuQrCode`：小红书二维码本地地址。
- `wechatName`：可选，覆盖公众号显示名称。

二维码图片放在 `public/uploads/subscriptions/`。修改后运行 `npm run content:check` 与 `npm run build`，重新部署。覆盖配置只支持公开订阅字段，不允许通过它增加内容记录或私密字段；本轮没有修改原数据库。

重新导出时只清理上一轮数据库导出的失效媒体，保留静态站自行维护的订阅素材和订阅覆盖配置。图片地址或分享链接变更时，需要同时更新二维码及对应按钮地址。

macOS 可使用系统 Core Image/Vision 重新生成或核对标准二维码，无需安装依赖；这些工具不参与平台构建：

```sh
swift scripts/qr-code.swift generate 'https://xhslink.com/m/你的分享链接' public/uploads/subscriptions/xiaohongshu-qrcode.png
swift scripts/qr-code.swift decode public/uploads/subscriptions/xiaohongshu-qrcode.png
```
