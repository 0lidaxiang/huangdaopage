# EdgeOne Pages 与静态托管

## EdgeOne Pages 构建

| 配置 | 值 |
| --- | --- |
| Git 仓库 | `0lidaxiang/huangdaopage` |
| 部署分支 | `master` |
| 项目根目录 | `./` |
| 框架 | 静态站 / Vite |
| 安装命令 | `npm ci` |
| 构建命令 | `npm run build` |
| 输出目录 | `dist` |
| Node.js | `22.11.0` |
| 环境变量 | `SITE_URL=https://正式域名`；根域部署无需设置 `SITE_BASE_PATH` |

构建仅读取已纳入仓库的公开内容源，不安装 MySQL、不运行 Python 导出、不连接本机数据库、不启动 Go。不要在平台设置数据库密码或旧站管理密钥。

配置依据为 2026-10-20 阅读的 [EdgeOne 官方 edgeone.json 文档](https://pages.edgeone.ai/zh/document/edgeone-json)，其中支持安装/构建命令、输出目录、预装 Node 版本和静态路径重写。根目录 `edgeone.json` 中的静态重写直接命中相应 `index.html`，不使用全站 SPA fallback。

## 页面路径与 404

每条公开路径均生成独立目录的 `index.html`，例如 `/depth/understanding-transformer/index.html`。历史 URL `/depth/understanding-transformer` 通过静态重写读取该文件，尾斜杠路径也可按目录索引读取。canonical 使用原来的无尾斜杠路径（首页除外），避免把两种形式视为两篇文章。

所有文章、节点、话题和路线都在构建时枚举生成。未知 slug、旧后台 `/admin`、旧 `/api` 请求没有对应文件，应返回 HTTP 404。`dist/404.html` 提供品牌一致的返回入口；按 [EdgeOne 官方自定义 404 文档](https://pages.edgeone.ai/zh/document/custom-404-page)，静态多页项目会自动识别该文件。

React Router 负责已加载页面之间的交互和导航；它不代替静态页面生成。详情页直接访问、刷新以及关闭 JavaScript 后阅读均使用实际 HTML。搜索查询参数在浏览器读取，不为每种查询生成页面，搜索页设置 `noindex,follow`。

## 域名根路径与仓库子路径

EdgeOne Pages 默认把本仓库产物托管在域名根路径，仓库名不会自动成为 URL 前缀：

```sh
SITE_URL=https://你的正式域名 npm run build
```

部署到其他托管服务的 `/huangdaopage/` 挂载路径时：

```sh
SITE_URL=https://你的正式域名 SITE_BASE_PATH=/huangdaopage/ npm run build
SITE_BASE_PATH=/huangdaopage/ npm run preview
```

该构建将链接、图片、JS/CSS、正文数据、搜索数据和 sitemap 全部加上前缀；将 `dist/` 的内容挂载到对应子目录。不要把子路径构建直接当作 EdgeOne 域名根目录产物上传。若在 EdgeOne 主站下挂子路径，需要在上层站点按该前缀挂载文件及应用 `dist/edgeone.json` 中的前缀配置。

本地 `preview` 从构建摘要识别前缀，也接受 `SITE_BASE_PATH`。切换挂载方式后重新构建，不能只移动 HTML 而保留旧资源路径。

## SEO、缓存与直接上传

所有页面有独立标题与描述，详情有 Article JSON-LD。设置 `SITE_URL` 后生成绝对 canonical、Open Graph URL 和完整 `sitemap.xml`、`robots.txt`。正式域名尚未确定时不会猜测域名；本地构建的 sitemap 暂为空，正式部署前请补上该变量并重建。

带内容哈希的 `/assets/` 缓存一年；HTML、静态数据和非哈希图片使用重新验证，避免新页面读取旧清单。更新内容或图片后完整替换部署产物。

直接上传时只上传 `dist/` 内部文件，保证 `index.html` 位于上传包根目录，详见[官方直接上传说明](https://pages.edgeone.ai/zh/document/direct-upload)。产物内附带的 `edgeone.json` 支持重写和响应头；安装/构建字段用于 Git 构建。

本次未访问腾讯云控制台或执行部署，托管平台上的实际发布结果等待后续授权后核对。

## 首次通过 Git 部署

1. 登录 EdgeOne Pages，在项目列表创建项目，选择导入 Git 仓库。连接 GitHub，并授权访问 `0lidaxiang/huangdaopage`，部署分支选择 `master`。操作入口参考[官方导入 Git 仓库说明](https://pages.edgeone.ai/zh/document/importing-a-git-repository)。
2. 根目录填写 `./`，按上表核对安装命令、构建命令、输出目录和 Node.js 版本。选择静态站/Other 或 Vite 静态构建，不需要 SSR 适配器、Functions 或旧后端。
3. 已有正式域名时，设置 `SITE_URL=https://正式域名`。没有域名时可先省略，完成首次部署后将平台分配的访问地址设置为 `SITE_URL` 并重新部署，再生成完整站点地图。
4. 开始部署，成功后核对首页、文章直达/刷新、演化、搜索及图片，并检查一条未知路径返回 404。绑定自定义域名时，按平台提供的 DNS 记录操作。

Git 连接建立后，向部署分支推送后续提交会触发平台构建。首次连接仓库和正式部署应由用户执行或明确授权；本仓库不配置自动调用平台部署的脚本，不需要在平台提供数据库或管理密钥。
