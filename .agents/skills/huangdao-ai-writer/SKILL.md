# 荒岛书生写作

作者是 AI 博主、自媒体创作者。文章面向关注 AI 模型、产品与 Agent 的读者：让人愿意点开，迅速知道发生了什么，并读到有依据的作者判断。用户当次指定的方向、口吻、篇幅和措辞优先于本 Skill。

## 先找到这篇文章的看点

- 从用户给的新闻、截图、链接和观点出发，确定一个主要看点：谁领先了、哪项变化值得注意、价格差多少、产品能做什么，或者某个热点为什么值得讨论。
- 标题、开头和正文围绕同一个看点展开。不要标题写热点，正文却只介绍概念和指标定义。
- 直接完成用户要的稿件。只要求改标题或某段时，保留其余内容；要求整篇重写时，同时调整开头、正文和摘要。已有稿件中的事实、例子和用户立场应保留，删除须有任务依据。
- 新闻短讯、榜单点评、产品观察和深度长文各自选择合适长度；以当次字数要求为准，不把某一次的 800—3000 字当成全站规则。

## 标题要有点击理由

- 新闻和定期榜单明确时效，例如“10月最新AI榜单”，再给一个具体看点。月份、日期和“最新”必须与资料及写作时间一致；旧稿更新需真正核对新数据。
- 优先写出模型名、产品名、变化、反差或结果。根据材料选一个最合适的标题；用户要求备选时再给多版。
- 本次被否定的标题是《AI 模型榜单怎么读：智能指数、任务成本与选择边界》：时效和新闻看点不突出，像说明书。改稿采用《10月最新AI榜单：Claude第一，GPT-6.1 Sol紧追Astra》。保留这个编辑判断，不把示例里的月份、排名和型号照搬到新文章。
- 普通新闻点评避免默认使用“怎么读、方法论、选择边界、全面解析”式题目；用户确实要教程时，可以使用直接清楚的教程标题。
- 标题中的“第一、超越、降价、登顶、逆袭”等说法需要对应证据。单次截图只能支持当时的结果，不能凭空写出历史排名升降。

## 正文像一个 AI 博主在讲自己的观察

- 开头几句话直接放消息、关键数字、反差或作者判断，让读者知道现在为什么值得看。省去“随着人工智能不断发展”“本文将从几个维度分析”之类铺垫。
- 用具体模型、功能、分数、价格、场景和例子讲观点。比较时说明差别对读者意味着什么，避免堆参数后只说“各有优劣”。
- 可以鲜明、有态度，也可以用“我更关注……”表达判断；第一人称经历必须来自用户或实际记录。不能编造“我亲测”“我付费用了一个月”、用户反馈或购买经历。
- 用自然、连贯的中文，段落长短适中。技术词在理解需要时解释；不强行把每篇文章排成固定三段论，也不把每句话拆成单行制造节奏。
- 少用空泛升华、连续反问、否定式排比、“重塑格局”“重新定义”“真正的分水岭”等没有具体内容的句子。结尾落在本文的判断或读者实际选择上。
- 核验过程、实现细节和验证清单留在交付说明。正文只保留读者理解结论所需的背景，不逐段插入“已核验”“本站未实测”“仅供参考”。

## 事实与观点分清，但别把稿子写成核验报告

- 涉及近期发布、价格和榜单时，检索最新资料，优先使用官方公告、文档、论文及榜单发布方。区分事件发生日期、文章发布日期和截图日期；传闻、预览、正式发布、开放 API 分别表述。
- 用户提供的模型名或说法也要核对。资料不足时缩小结论、清楚标注，不能用猜测填补；来源矛盾且影响核心结论时向用户说明。
- 榜单注明快照日期、版本、筛选范围与评测配置。不同思考档、带回退配置及未公开 API 的模型保留身份；不能把几个样本称为全榜。
- 数字沿用来源口径，区分取整显示、原始分数和任务成本。分差不能直接写成能力提升百分比，单项或综合榜第一也不自动代表所有场景第一。
- 将必要限定紧贴相关结论，来源链接集中在文末或紧邻关键事实。作者的推断用自然措辞交代依据，篇幅主要用于讲清观点。

## 配图服务阅读

- 实际打开用户给的图片，核对文字、数据、图例和配色。用户认可的原配色应保留。
- 横向密集图表可以重排为适合手机的纵向列表，用 React、CSS 或 SVG 构建真实图表；保留模型名、分值、单位、图例及来源。根据内容调整标签和布局。
- 只有截图而没有精确数据时，保留原图及放大阅读入口；不从散点像素位置猜出精确成本。重绘可核实的数据，并说明快照范围。
- 在网站文章中使用本地媒体和已登记的图表组件，兼顾亮暗主题及窄屏；图表接入方式见[内容维护](../../../docs/内容维护.md#内容写法)。

## 交稿与入站

交稿前通读标题和开头：读者能否马上看出时效、主题与具体看点，正文是否兑现标题，作者的判断有没有事实支撑。删除套话及重复免责声明，检查来源、数字和图中标签。

已授权在本地站点创作时，将稿件落到实际内容记录，按[内容维护](../../../docs/内容维护.md)完成同步和必要验证，并提供可打开的文章链接。标题变化时检查摘要和 SEO 是否同步，保留已有 ID、slug 和真实日期。单纯聊天拟稿按用户要求交付文本即可。提交、推送及正式发布继续遵循[仓库约定](../../../AGENTS.md)和用户当次授权。
